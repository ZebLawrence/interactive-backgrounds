# Hangar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An eighth interactive background, `hangar/html/`: a remastered Doom E1M1 techbase on Phobos, built from scanned PBR assets on the traced real layout, toured forever by a camera that walks it like a person.

**Architecture:** The level is a hand-traced JSON of Doom-style sectors (polygons with floor/ceiling heights and material tags). Pure, Three-free modules turn it into geometry data, a navigation graph, a seeded tour and a walking camera; these are unit-tested with `node --test`. Browser modules turn that data into meshes with real PBR materials (parallax relief, reflection probes), place lights, the slime, the Phobos exterior and Mars, scatter props, and render at native resolution through a small post stack.

**Tech Stack:** Three.js r170 from jsDelivr by import map (WebGLRenderer), ES modules, no page build step; `KTX2Loader` (UASTC textures), `GLTFLoader` + `MeshoptDecoder`; Node 25 `node:test` for pure modules; offline asset tools `toktx` (KTX-Software) and `npx @gltf-transform/cli`; Chrome DevTools MCP for visual verification.

**Spec:** `docs/superpowers/specs/2026-11-01-hangar-design.md`. Read it and `guidelines.md` before starting any task.

## Global Constraints

- Folder `hangar/`: page in `hangar/html/` (`index.html`, `styles.css`, `js/*.js`), level data in `hangar/html/data/`, assets in `hangar/html/assets/`, offline tools in `hangar/tools/`, tests in `hangar/tests/`.
- No page build step. Three.js 0.170.0 from `https://cdn.jsdelivr.net/npm/three@0.170.0/` via import map. Every module URL is versioned `?v=N` in the import map, and N is bumped whenever any JS changes.
- Pure modules (`rng.js`, `level.js`, `navgraph.js`, `tour.js`, `walker.js`, `scatter.js`, `lightplan.js`) must not import `three`. They are tested with `node --test hangar/tests/`.
- Units are metres. Doom units convert at `UNIT = 0.03` m (a 56-unit player is 1.7 m).
- Native resolution: the render target is window size × `devicePixelRatio` (capped at 2), never a lower internal resolution in the default mode. If the effects don't fit, the frame rate gives first (a steady 30 fps is acceptable).
- Texel density ≥ 1024 px per metre on every surface the camera passes within 2 m. Mipmaps on, `anisotropy = renderer.capabilities.getMaxAnisotropy()` on every texture.
- Camera eye height 1.7 m, walking pace ≤ 1.0 m/s.
- Licences: CC0, CC-BY-4.0 (Sketchfab CC-BY allowed), or public domain (NASA/JPL/USGS). No NC, no ND. No id Software files or art, no WAD in the repo. Every asset credited in `hangar/README.md`.
- Single files < 100 MB. Whole `hangar/html/assets/` < 600 MB.
- No sound. No Swift port. No creatures.
- Menu: New Tour (reseed), Emergency Power (`E`), Low Power (30 fps, `pixelRatio` 1, nearest 2 shadow casters), Full Screen. URL flags: `?seed=N`, `?emergency` / `?noemergency`, `?lowpower`, `?perf`.
- Never push. Commit on branch `hangar-design`; the owner says when to push.
- `guidelines.md` applies in full (nothing floats, contact shade, NaN guards, `vMapUv` in r170, backticks in GLSL comments, wait for a real window size, fixed-step simulation).

## Review Focus

1. **Window size of 0×0 at load or a resize mid-tour:** build waits for a real size; a resize keeps the walker's state (no restart, no jump). Test in Task 1 (shell) and Task 13.
2. **A tab hidden for hours, then shown:** `dt` is clamped to 1/15 s, the walker resumes from where it was with no teleport, and shader time wraps hourly. Walker test in Task 5 (`step` with a huge dt).
3. **A click that hits nothing reachable** (the sky, a wall, the slime pool, a ceiling): the camera goes to the nearest reachable floor point within 3 m of the hit, otherwise ignores the click. Test in Task 5 (`resolveClickTarget`).
4. **An asset that fails to load** (404, slow network): the scene still starts with a neutral fallback material, the error shows in `#error`, and the tour runs. Test in Task 6 (`assets.js` fallback) and verification in Task 7.
5. **A cursor that sits still for hours over the page:** the tour never stops. Rest means only "came to rest after moving", a single pause of 4 s. Test in Task 5.

### Task 5: Tour, walking camera and mouse cues

**Files:**
- Create: `hangar/html/js/tour.js`, `hangar/html/js/walker.js`, `hangar/tests/tour.test.mjs`, `hangar/tests/walker.test.mjs`
- Modify: `hangar/html/js/scene.js` (drive the camera from the walker; screen-to-world pick for clicks)

**Interfaces:**
- Consumes: `Graph`, `findPath`, `nearestNode`, `clearanceAt`, `makeRng`, `Level.pois`.
- Produces: `makeTour(pois, rng, { memory = 4 }) -> { next(fromPoi?): poi }`: weighted random pick, never one of the last `memory` visited, nearer pois weighted higher (weight ∝ 1 / (1 + distance / 25 m)), `window`/`view` kinds weighted ×2.
- Produces: `class Walker { constructor(level, graph, tour, rng); step(dt, input) -> Pose; goTo(x, z); state: 'walking'|'pausing'|'looking'|'riding' }` where `input = { gaze: { yaw, pitch } | null /* cursor direction, radians relative to view */, restedAt: { x, y, z } | null /* set once when the cursor comes to rest after moving */, click: { x, y, z } | null }` and `Pose = { x, y, z, yaw, pitch, roll }`.
- Produces: `resolveClickTarget(level, graph, hit: { x, y, z } | null) -> { x, z } | null`: nearest node within 3 m horizontally of the hit, otherwise `null`.
- Movement values: path through node positions smoothed with centripetal Catmull-Rom, then pushed off walls to keep `clearanceAt >= 0.35`; cruise 0.85 m/s, varied ±15% per leg by `rng`; acceleration ≤ 0.4 m/s², slowing to 0.4 m/s through turns sharper than 45°; stairs slow to 0.5 m/s. Step bob: vertical 0.025 m at step frequency speed / 0.65 m, lateral sway 0.012 m at half that; both fade in and out with speed. The body yaw follows the path tangent through a critically damped spring (time constant 0.6 s); the head yaw leads it, looking 1.2 s ahead along the path; random glances (every 6–15 s, ±35°, held 1–3 s). At a poi it pauses 4–12 s looking at `poi.look`, pitching up when the ceiling above is more than 3× eye height. Gaze bias adds up to 15° toward `input.gaze`, eased. `restedAt` → pause 4 s looking there, then carry on. `click` → `goTo`, then resume touring from there.

- [ ] **Step 1: Failing tests** (`walker.test.mjs`, simulate at 1/60 s on the real level, seed 1): over 30 simulated minutes speed never exceeds 1.0 m/s, `clearanceAt` at the pose never < 0.35, no NaN in any pose, yaw rate never > 90°/s, and the walker reaches at least 6 distinct pois; over 2 simulated hours with `restedAt` sent once at the start and never again, the walker spends < 10% of time paused longer than 12 s at once (the tour never stalls); `step(3600, {})` once (a tab hidden for an hour) moves the pose by ≤ 1/15 s of travel; `resolveClickTarget` returns `null` for a hit in the sky 50 m above the courtyard and for a hit in the middle of the slime pool more than 3 m from the walkway, and a node for a hit on the start-room floor. `tour.test.mjs`: no poi repeats within 4 picks over 1 000 picks; window/view pois are picked more often than room pois.
- [ ] **Step 2: Run** → FAIL. **Step 3: Implement `tour.js`, `walker.js`, `resolveClickTarget`.** **Step 4: Run** → PASS.
- [ ] **Step 5: Wire into `scene.js`.** Gaze comes from the pointer's offset from screen centre; `restedAt` fires once when the pointer has moved more than 30 px within the last second and then stays within 4 px for 0.8 s; a click raycasts against `colliders` (Task 3) and passes the hit to `resolveClickTarget`.
- [ ] **Step 6: Verify:** watch 3 minutes of greybox tour live at 60 fps and step `hangar.run(600)` repeatedly. Expect: no constant-speed gliding, visible head turns before body turns, pauses at windows, climbs the stairs, rides the lift, never touches a wall. Click the floor across a room → it walks there.
